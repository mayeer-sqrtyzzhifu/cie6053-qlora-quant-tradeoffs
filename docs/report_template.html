1　引言

1.1　问题与背景

在 12 GB 级消费级显卡上微调 1.5B 规模的指令模型，显存是第一个约束：BF16 权重、优化器状态与激活值三者叠加， 很容易越过预算。QLoRA 的做法是把基座压到 4-bit、冻结权重、只训练低秩适配器，并配合分页优化器吸收显存尖峰， 使这类硬件上的微调成为可能 [1]。

能跑通不等于划算。四种格式同时改变权重精度、常驻显存和矩阵乘路径：4-bit 权重在计算前要反量化， 计算仍在 BF16 完成，省下的显存未必转化为速度；INT8 的实现路径又不同。再叠加 LoRA 秩与样本量的边际收益递减， "在 12 GB 预算下应该怎么配"不能靠直觉回答。

课程中的量化讨论多集中在推理侧（INT8 部署、算子优化）。训练侧四种基座精度在同一流程下的横向对比， 以及"省下的显存是否换来了速度"这个问题，在消费级硬件上缺少可复现的定量证据。本文用一组受控实验补上这一块。

1.2　研究问题

RQ1　在 12 GB 预算下，INT8、NF4、FP4 相对 BF16 LoRA 的精度代价与显存收益分别是多少？精度损失是否落在 1 个百分点以内？

RQ2　LoRA 秩从 8 增到 32、训练样本从 500 增到 4,000 时，准确率的绝对增益在哪一侧更大？（两种变化对应的训练计算量不同，单位成本比较不在本实验设计内。）

RQ3　在已测配置中，准确率、显存、吞吐是否存在同时占优的配置？两种评估协议（各自格式 / 统一 NF4）是否会改变结论？

1.3　课程主题对应

本工作覆盖四个主题。量化：BF16/INT8/NF4/FP4 的统一流程对比。 内存瓶颈：区分权重常驻与激活峰值，并回答预算内可支持的最大批量。 用于 AI 加速的 GPU：消费级 GPU 的功耗、利用率、SM 时钟与降频。 神经网络：QLoRA 微调与分类任务的完整训练与评估链路。

2　相关工作与本工作的起点

LoRA 把权重更新分解为低秩乘积，只训练适配器而冻结基座 [3]，PEFT 提供了标准实现 [6]。 LLM.int8() 用分块混合精度把矩阵乘降到 INT8，并对激活中的离群值保留高精度计算 [2]； QLoRA 在此基础上提出 NF4 数据格式与双重量化，使大模型能在单卡上微调 [1]，bitsandbytes 是其主要实现 [5]。 这些工作回答的是"能否在低显存下训练"，评测以困惑度与下游精度为主；本文关心的是 "同样的训练流程下，四种基座精度的代价结构如何不同"，并把训练与推理的吞吐、常驻与峰值的显存分开测量。

3　方法

3.1　数据与预处理

任务为 AG News 四分类（World / Sports / Business / Sci/Tech）[8]，使用官方划分：训练 120,000 条、测试 7,600 条， 四类各占 25%。抽样顺序是：先从清洗后的训练池分层抽出 1,000 条验证集，再在剩余池中分层抽出四档训练子集 （500 / 1,000 / 2,000 / 4,000），四档互为嵌套。由于 AG News 训练池内部存在重复文本， 抽样后额外检查了验证集与四档子集的文本重叠，发现有 1 条重复，已用池中未被占用的样本替换； 修复后四档重叠均为 0（见表 1）。

原始文本有两类系统性噪声：约 11% 的训练文本含 CSV 转义残留的反斜杠，另有数万处残缺 HTML 实体（如 #36; 应为 $）。 训练与测试施加相同的规范化（反斜杠转空格、实体还原、空白压缩），随后以归一化文本比对训练池与测试集， 剔除归一化后与测试样本完全相同的 28 条训练样本（精确匹配，未做模糊相似度检测）。样本的 prompt、completion 与 EOS 合计不超过 256 token；少量超长样本收缩新闻正文， 而不是截断标签，以保证监督信号完整。各步计数写入数据审计，见表 1。

3.2　提示词与监督信号

提示词使用 Qwen2.5 官方 chat template：用户轮包含任务指令与新闻正文， add_generation_prompt=True 使类别判定落在 assistant 轮的第一个 token； 微调目标是类别名（如 World）加 <|im_end|>。训练与评估共用同一构造函数， 判定位置一致，因此零样本与微调后的准确率可以直接比较。

训练只对 completion 计算损失，prompt 部分标签置为 -100，模型学的是"输出类别名"而不是复述指令。 评估不做文本生成：取最后一个位置在四个类别首 token 上的 logits 取 argmax，与监督位置完全对齐，也避免了生成式解析的误差。

3.3　量化格式与 LoRA

基座为 Qwen2.5-1.5B-Instruct [7]。四种基座精度：BF16 LoRA（不量化，作为对照）、 INT8（load_in_8bit，bitsandbytes 的 MatMul8bitLt）、 NF4（4-bit NormalFloat + 双重量化）、FP4（4-bit 浮点）。4-bit 的计算 dtype 统一为 BF16； INT8 路径在库内部会把输入转为 FP16 计算，数值行为与 4-bit 不同，结果中与 4-bit 分开解读。

LoRA 作用于注意力层的 q_proj 与 v_proj，秩 r ∈ {8, 16, 32}，lora_alpha = 2r， dropout 0.05；优化器 paged_adamw_8bit [4]（分页 8-bit 优化器），开启梯度检查点，3 个 epoch，余弦调度，学习率 2e-4， warmup 3%，max_grad_norm 0.3。

3.4　两种评估协议

若所有适配器都用统一 NF4 基座评估，BF16 适配器会额外承受一次量化误差，绝对精度被低估； 若都用各自格式评估，跨格式比较又依赖不同基座。因此同时报告两种结果：native 用训练时的格式加载基座并评估对应适配器（主结果）， cross_nf4 把全部适配器放在 NF4 基座上评估（交叉检验）。两者在同一设备上执行， 非量化分支显式搬到 GPU 并加断言，避免 CPU 前向污染吞吐。

3.5　指标口径与统计方法

精度侧报告 accuracy、balanced accuracy、macro-F1、每类召回与 4×4 混淆矩阵，并保存 7,600 条逐样本预测。 显存按三层记录（定义见 4.1）：模型常驻、训练分配器峰值与设备占用。 吞吐分两条轴：训练吞吐按纯训练时间计（不含验证评估），推理吞吐指分类前向（prefill，不含自回归解码）。 功耗、温度与利用率由训练期每 2 秒一次的采样记录；完整的测量范围与边界见附录 B 表 B1。

关键配置各跑三个种子以估计训练随机性；配置间差异用 seed=42 的同一批逐样本预测做 McNemar 精确检验。 需要注意两类统计单位不能混用：配对检验回答"这一次运行的逐样本差异是否超出偶然"， 三个种子的均值差只描述训练随机性。一次比较 6 组会抬高假阳性，因此同时给出 Holm 校正后的 p 值， 并以校正结果判断是否存在显著差异。

4.1　硬件与软件

单块 NVIDIA GeForce RTX 5070 Ti Laptop GPU（sm_120，Blackwell），显存 11.94 GB； nvidia-smi 报告的功耗上限约 140 W，训练期采样峰值为 141.9 W（瞬时尖峰，未触发降频标记）。 驱动版本未写入运行快照；实验后在同一台机器补记：驱动 596.49 / CUDA 13.2 （输出见 outputs/logs/driver_info_2026-11-18.txt）。软件为 Python 3.11.18、PyTorch 2.11.0+cu128、Transformers 5.23.0、PEFT 0.21.3、 bitsandbytes 0.50.2、datasets 5.2.0、accelerate 1.15.0，完整清单见 environment.yml。 每次运行另存配置快照与环境快照，便于回溯。

显存分三层记录，回答不同问题： ① 模型常驻（加载后、训练前的 torch.cuda.memory_allocated() 增量）——比较不同精度下权重与适配器的开销； ② 训练峰值（torch.cuda.max_memory_allocated()）——比较训练期张量分配需求； ③ 设备占用（nvidia-smi memory.used 采样，含 CUDA 上下文、驱动与同机其他进程）—— 判断真实显卡还剩多少余量、何时会 OOM。三者不能互相换算，也不能相减。

单位说明：本报告中的 GB/GiB 均按 1024³ 字节计（即 GiB），卡容量为 11.94 GiB； "12 GB 预算"指分配器峰值口径下的工程预算，而不是物理显存容量的完整判据—— 判断能否再加 batch 应看设备占用（表 8 的最后一列）。

6　讨论

6.1　按约束条件选配置

把"12 GB 分配器峰值预算"和"1 个百分点精度预算"作为约束，推荐不是唯一的，取决于哪个资源更紧； 需要说明的是，全部候选的分配器峰值只有 3.86–6.97 GB，本实验的 12 GB 预算对它们都不构成约束， 真正接近 11.94 GiB 上限的是整卡设备占用（11.07–11.58 GiB）。候选与筛选结果见表 10。{{REC_TEXT}}

6.2　结果为什么是这样

4-bit 与 BF16 的差别有两处：权重常驻（2.88 GB → 1.52 GB）与每次矩阵乘前的反量化。 观测到的吞吐与能效下降与"反量化带来额外开销"的解释一致，但本次没有单独测量这部分开销， 也不能排除实现与调度因素，因此不把它写成已确认的因果。峰值显存同时受激活与梯度检查点影响， 只看峰值会低估量化的价值，因此本文把常驻与峰值分列。INT8 的问题在实现路径：MatMul8bitLt 先把 BF16 输入转成 FP16 再计算， 额外转换使它既没有 4-bit 的显存优势，也没有 BF16 的速度。这一解释与观测一致 （SM 利用率 47.8%、训练吞吐 7.6 samples/s），但转换开销本身没有被单独测量。

6.4　局限

四种格式实际是"数值精度 + 软件执行路径"的组合：INT8 在库内部转 FP16 计算、4-bit 需要反量化、 BF16 无转换，因此格式之间的差异不能单独归因于"位宽"，也不能外推到其他量化实现； 本实验只覆盖一个 1.5B 模型、一个数据集和 256 token 的序列上限，结论不宜外推到更长上下文或更大模型； 只使用了 bitsandbytes 一种量化实现，未与 GPTQ、AWQ、GGUF 等对比；推理指标只测分类前向，未测自回归解码； batch 固定为 4，4-bit 省下的显存没有转化为吞吐，这一点只由两次 batch 8/16 探索运行给出边界； 硬件是消费级笔记本 GPU，格式间运行分散在约 2.5 小时内，日志未标记降频（峰值温度 79–84 °C）， 格式间吞吐差也远大于同格式的种子内波动，但跨时段比较仍不如同一批次内严格； 部分配置为单种子（11 个配置中 7 个单种子，占 19 次运行的 7/19），相关趋势属于工程测量； OFAT 设计只能回答主效应，不能回答量化格式与样本量的交互（只有 NF4 跑了四档样本量）； batch 8/16 各只有 1 次单种子探索，且 bs16 设备峰值已达 11.56 GiB，"预算内最大批量"只能算粗略边界； fp32 对照只覆盖 400 条样本的单次评估；主推荐 fp4_r16_n2000 是在测试集上比较 11 个候选后选出的， 其 0.9121 的准确率对这种选择存在选择性偏差；0.30 pp 的工程等价阈值与训练时长 tie-break 均为事后规则， 不是实验前预注册； 超参与训练配置只依据验证集与训练损失确定，未在测试集上调参；但最终展示配置（第 6.1 节）是在测试集准确率上比较候选后选出的，这一点已在上句披露。
