### 异常与修复 1：显存分配器碎片导致分页（16:00–16:05）

- 现象：首次启动后步速从 3.3 it/s 掉到 **1.0 s/it**，`nvidia-smi` 显示显存 **11.88 / 11.94 GB**、
  利用率 99% 但功耗只有 **70 W**（正常应 ~127 W）。
- 诊断：变长序列（88–253 token）+ 梯度检查点使 PyTorch 缓存分配器产生大量碎片，
  reserved 显存被撑满；Windows/WDDM 随后向系统内存分页，表现为「高占用、低功耗、慢步速」。
- 处理：终止该次启动（首个 run 尚未产出结果，无数据损失）→ 在 `02_train.py` / `03_evaluate.py`
  的 `import torch` 之前设置 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` → 以
  `--plan --explore --resume` 重启。
- 结果：首个 run 峰值显存回到 **6.968 GB**，步速 **6.3 it/s**，纯训练 237 s；功耗 127 W、峰值 82 °C。
- 留档意义：该环境变量是复现条件之一，须写入报告 §4.2 与 `environment.yml` 的说明（脚本已内置默认值）。

### 异常与修复 2：训练后 val 评估被 reserved 显存拖慢（16:12–16:16）

- 现象：第 2 个 run 的 val 评估从 0.4 s/batch 掉到 **4.5 s/batch**（63 batch 需 ~5 min），
  `nvidia-smi` 显示 11.83/12.23 GB、利用率 99% 但功耗仅 **55 W**。
- 诊断：训练结束时分配器仍持有约 7 GB 的 reserved 块；评估阶段要新分配
  logits（batch 8 × 256 × 151k 词表，约 1 GB），叠加后超过 12 GB 预算，被 WDDM 分页。
- 处理：在 `trainer.evaluate()` 之前调用 `torch.cuda.empty_cache()`（`02_train.py`）。
  重启后用 `--resume` 跳过已完成的 run 1。
- 结果：run 2 的 val 评估降到 **6.63 s**（原 24.55 s / 异常时 ~300 s）；纯训练 225.29 s、吞吐 26.63 sa/s。
  说明：`eval_time_s` 只作留档，吞吐一律按纯训练时间计算，不受该问题影响。

### 异常与修复 3：同进程串跑污染显存读数（17:10–17:20）

- 现象：跑完 7 个 run 后发现显存读数随 run 顺序单调增长：
  nf4 常驻 **5.02 GB**、峰值 **7.35 GB**（fresh 进程同一配置应为 1.5 / 3.9 GB 量级），
  bf16 峰值也从 6.97 涨到 7.40 GB，int8 常驻在 3.87–5.45 之间跳动。
- 诊断：批处理在同一 Python 进程里串行调用 `run_once`，上一轮的分配器残留（optimizer/paged 状态、
  缓存块）未完全释放，`torch.cuda.memory_allocated()` 把它们算进了下一轮。
  **显存是本项目的核心指标（C2）**，该污染不可接受。
- 处理：
  1. 批处理改为**每个 run 一个独立子进程**（`subprocess.run` 递归调用本脚本的单 run 模式），
     进程退出即彻底释放；失败重试与 `FAILED_RUNS.md` 逻辑移到父进程。
  2. 常驻显存改为**加载前后差值**（`gc.collect()` + `empty_cache()` 后取基线），
     不再用绝对值。
  3. 清理被污染的 7 个训练 JSON 与 logs/checkpoints，整批重跑。
- 代价：每个 run 多一次模型加载（约 5–10 s）；预计训练总时长增加约 3–5 分钟，可接受。

### 异常与修复 4：子进程进度条反压导致假性变慢（17:20–17:30）

- 现象：改用子进程隔离后，run 1 正常（26.5 sa/s、6.968 GB），但 run 2 又出现
  「利用率 98%、功耗 74 W、显存 11.8 GB、步速掉到 0.6–2.3 it/s」。而进程全部退出后
  整卡占用立刻回落到 343 MiB，说明并非显存未回收。
- 诊断：批处理把子进程 stdout 接到父进程的 `Tee-Object`，tqdm 每步输出一行进度条
  （单 run 上千行）持续写入管道/任务缓冲，形成**反压**，子进程周期性阻塞在 stdout 写操作上：
  GPU 空转 → 功耗下降、步速骤降。日志越大越慢，解释了「越跑越慢」的现象。
- 处理：
  1. `TrainingArguments(disable_tqdm=True)`，子进程只输出每 run 的摘要（日志从数千行降到 238 行）。
  2. 保留 R3-26 的子进程隔离（显存读数仍需干净），并新增 `wait_gpu_idle()` 闸门：
     每个 run 启动前等整卡占用降到 2.5 GB 以下（最多 180 s），防止驱动回收滞后。
  3. `gpu_trace.csv` 增加整卡显存列，便于事后判定是否发生分页。
- 结果：run 2 恢复正常（**23.85 sa/s**、峰值 6.968 GB、126.1 W），run 3 运行中（91% 利用率、128 W）。
